# ТЗ: Безопасный переход на Tauri с сохранением Python-версии

Данный документ описывает стратегию параллельного сосуществования двух кодовых баз (Python/PySide6 и Rust/Tauri) в рамках одного репозитория для обеспечения 100% возможности отката.

---

## 1. Стратегия разделения кодовых баз (Side-by-Side Coexistence)

Чтобы гарантировать безопасность, существующий код Python **не модифицируется и не перемещается**. Все работы по Tauri ведутся в изолированной новой папке.

### Структура репозитория:
```text
/client_manager (корень репозитория)
  ├── README.md                 # Общий лендинг репозитория
  │
  ├── /FinanceFugue             # [Текущая версия] Полный проект на Python/PySide6
  │     ├── src/
  │     ├── main_pyside.py
  │     └── ... (все файлы Python-версии остаются нетронутыми)
  │
  └── /FinanceFugue_Tauri       # [Новая версия] Изолированный проект на Rust/Tauri
        ├── src-tauri/          # Бекэнд на Rust (конфигурация Tauri, логика)
        ├── src/                # Фронтенд на HTML/CSS/JS (Svelte или React)
        ├── package.json
        └── TAURI_MIGRATION_SPEC.md  # Этот документ
```

---

## 2. Безопасность и совместимость данных (Zero-Conflict DB)

Обе версии будут использовать **одно и то же физическое расположение базы данных**, что позволит переключаться между ними без потери данных пользователей.

* **Путь к БД (Windows):** `%LOCALAPPDATA%\FinanceFugue\pro_database.json`
* **Файл блокировки:** `%LOCALAPPDATA%\FinanceFugue\pro_database.lock`
  * Python-версия блокирует файл через `msvcrt` (Windows).
  * Rust-версия будет блокировать тот же файл через крейт `fs2` или `single-instance`.
  * *Результат:* Вы не сможете запустить Python-версию и Rust-версию одновременно (одна заблокирует запуск другой, предотвращая порчу БД).

## 3. Этапы реализации в папке `FinanceFugue_Tauri`

### Этап 1: Инициализация окружения
В корневой папке репозитория запускается команда создания Tauri-приложения:
```bash
# Будет создана папка FinanceFugue_Tauri
npm create tauri-app@latest FinanceFugue_Tauri
```
* **Выбор стека:** 
  * Frontend Language: `TypeScript`
  * Package Manager: `npm`
  * UI Template: `Svelte` (рекомендуется за лаконичность) или `React`.
  * UI Styles: `Tailwind CSS`.

### Этап 2: Перенос моделей и бизнес-логики (Rust)
Файлы переносятся из `/FinanceFugue/src` в `/FinanceFugue_Tauri/src-tauri/src/`:

1. **Модели данных (`models.rs`):**
   Создание структур `Client`, `Order`, `Payment` с использованием `serde` для сериализации в JSON.
2. **Менеджер БД (`storage.rs`):**
   Реализация загрузки, сохранения (с атомарной записью во временный файл `.tmp`) и авто-бэкапов.
3. **Логирование (`logger.rs`):**
   Настройка `tracing-subscriber` с выводом логов в `%LOCALAPPDATA%\FinanceFugue\logs\crm_YYYY-MM-DD.log`.

### Этап 3: Создание моста IPC (Tauri Commands)
В файле `main.rs` регистрируются команды, к которым фронтенд будет обращаться:
* `get_clients()` — возвращает список клиентов.
* `save_client(client)` — сохраняет/обновляет клиента.
* `delete_client(id)` — удаляет клиента.
* `add_payment(client_id, payment)` — добавляет транзакцию.
* `open_client_folder(path)` — вызывает Проводник ОС для открытия папки.

### Этап 4: Разработка интерфейса (Фронтенд)
Интерфейс верстается на Svelte/React с использованием Tailwind CSS в стиле **Dark Material**:
* Боковое меню (список клиентов с поиском и сортировкой).
* Главный дашборд статистики.
* Профиль клиента с таблицей заказов и логом платежей.
* Дерево файлов с обработкой Drag-and-Drop (пути передаются в Rust для копирования).

---

## 4. План тестирования и отката

1. **Тестирование совместимости:**
   * Запустить Python-версию, добавить клиента, закрыть приложение.
   * Запустить Rust-версию, проверить, что клиент отображается корректно.
   * Добавить заказ в Rust-версии, закрыть.
   * Запустить Python-версию, проверить корректность отображения нового заказа.

2. **Экстренный откат:**
   * Если в Rust-версии обнаруживается критический баг перед релизом, разработчик просто собирает EXE из папки `/FinanceFugue` (Python). База данных пользователя остаётся валидной и работоспособной.
