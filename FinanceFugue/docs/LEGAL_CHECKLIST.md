# Legal Checklist — FinanceFugue v1.0.0

> Это **не юридический документ**, а developer-side tracking-list для
> выпуска коммерческой версии. Каждый пункт содержит ссылку на
> требование и текущий статус.

---

## 1. Open Source обязательства (LGPL v3, PySide6)

Требование: при распространении бинарника под LGPL нужно предоставить
пользователю возможность пересобрать/переподключить Qt-библиотеки.

| # | Что сделано | Где |
|---|---|---|
| ✅ | Исходники проекта доступны (или планируются в GitHub) | `README.md` |
| ✅ | `LICENSE` файл в дистрибутиве | repo root |
| ✅ | `THIRD_PARTY_LICENSES.txt` с лицензией LGPL v3 текстом | repo root |
| ✅ | Упоминание LGPL в About-диалоге | `src/dialogs/about.py` |
| ✅ | Упоминание LGPL в EULA | `EULA.md` §4 |
| ✅ | PySide6 НЕ модифицирован (получается из PyPI) | `requirements.txt` |
| ⚠️ | Убедиться, что в EXE PySide6 bundling не делает его «производной работой» | Документировать в THIRD_PARTY_LICENSES (ссылка на исходники PySide6) |
| ⚠️ | Рассмотреть альтернативу: static-linking Qt → требуется коммерческая Qt-лицензия | Опционально (Qt Commercial) |

**Статус:** базовое соответствие есть. Для production-релиза юрист должен
проверить формулировки в `EULA.md` §4 и `THIRD_PARTY_LICENSES.txt`.

## 7. Обязательный юридический чек-лист для production

> Перед публичным коммерческим релизом — **обязательно** проверить
> с юристом. Ниже — что **разработчик не может решить сам**:

- [ ] EULA.md прочитан юристом по предмету:
  - [ ] недвусмысленность формулировок
  - [ ] соответствие законодательству целевого рынка
  - [ ] действительность соглашения в разных юрисдикциях
- [ ] Privacy.md / PRIVACY-политика по GDPR/ФЗ-152
- [ ] Лицензионная чистота всех зависимостей (pip-licenses / scancode)
- [ ] Страхование ответственности (если нужна коммерческая дистрибуция)
